# B2B 实验规范

> 先定决策，再定单元；先证数据，再读效应；最后把决策和证据一起沉淀。
> 这是 5 分钟操作卡。深度内容按 `references/INDEX.md` 的路径按需读取，不要从完整规范的第一页读到最后一页。

## 0. 六步工作流

1. **说清决策**：结果阳性、阴性、持平分别做什么；如果答不出，先不要开实验。
2. **选对单元**：干预在哪一层发生、干扰在哪一层传播，就在哪一层随机；默认企业/账户，而不是用户。
3. **冻结证据**：一个主指标、一个窗口、一个分析总体、一个估计量、一个决策阈值，曝光前写进预注册。
4. **先过数据门禁**：SRM、曝光、平衡性、污染、重复账户、血缘，任何 S1 都先停止读数。
5. **再读效应**：ITT 为主，报告绝对提升、相对提升、95% CI、MDE、样本量和业务价值。
6. **做可逆决策**：全量 / 定向 / 迭代 / 停止 / 复测，并留下文档、SQL、Dashboard、知识卡。

## 1. 何时用，何时不用

**用**：

- 设计 A/B、cluster、switchback、geo、holdout 实验。
- 评审实验设计、读数、全量决策。
- 审计 SRM、曝光、平衡性、污染、重复账户、指标血缘。
- 写实验规范、字段字典、预注册模板、决策记录。
- 搭实验平台 schema、门禁、RACI、30/60/90 天落地计划。
- 业务杠杆涉及询盘报价、企业账户、商家、定价、账期、履约、销售区域。

**不用**：

- 纯 B2C 增长实验，没有账户/商家/合同层。
- 只要求“跑一段 SQL”或“画一张图”，没有因果或决策问题。
- 需要法律意见的定价、数据合规判断；本 Skill 只提示应找法务/财务/安全复核。

## 2. 三条工作流

### A. 设计新实验

1. 写决策、基线、受影响人群、不做的替代方案。
2. 写可证伪假设：机制、杠杆、人群、主指标、MDE、窗口、护栏、反证条件。
3. 选单元、查干扰、算样本：baseline、方差/ICC、分流、CUPED、流失、cluster DEFF。
4. 定指标树、预注册、过 G1；输出一页纸 + 61 字段 + 功效附录。

### B. 审计已有实验

1. 用 61 字段重建实验，缺字段先标记。
2. 跑 `references/20-data-quality.md` 评分卡；S1 阻断读数。
3. 用正确估计量重算：ITT、cluster-robust、delta、CUPED。
4. 查护栏、子群、多重比较、长期窗口，输出门禁表、修正效应、决策建议。

### C. 建制度或平台

1. 从 `references/60-field-dictionary.md` 起步，适配字段名和 owner，不静默删字段。
2. 加门禁、RACI、预注册、归档：`references/80-governance-platform.md`。
3. 加模板、SQL、平台 schema：`references/50-templates.md`。
4. 先试点 2 个实验，量预注册率、DQ 通过率、决策时长、归档率，再按 30/60/90 天推进。

## 3. 八条硬规则

1. **决策先行**：说不出结果对应的动作，不要实验。
2. **单元对齐**：默认企业/账户；供给、库存、价格、区域政策造成干扰时，用商家、geo、switchback。
3. **先预注册**：主指标、窗口、总体、估计量、子群、阈值、计划哈希，曝光前冻结；事后改动一律标记 amendment，降级为探索性。
4. **SRM 是门禁**：p < 0.001 先查分流，不要靠重加权“修复”；未过 SRM 不读主指标。
5. **ITT 为主**：曝光/依从/TOT/per-protocol 只作次要解释，必须标注。
6. **聚类和比率要正确**：账户/商家/geo 随机、订单/用户层结果，用 cluster-robust；比率指标用 delta 或 bootstrap，不要直接 t 检验。
7. **效应要完整**：绝对提升 + 相对提升 + 95% CI + MDE + 样本 + 业务价值；只报 p < 0.05 不算结论。
8. **护栏有牙齿**：每个护栏有 owner、阈值、熔断动作；护栏 owner 能否决全量。

## 4. B2B 默认值

| 杠杆 | 默认单元 | 主指标候选 | 护栏 |
|---|---|---|---|
| 搜索/推荐/工作台 UI | 企业/账户 | Q2O 转化、报价接受率、净 GMV | 取消率、纠纷率、卖家报价率 |
| 定价/阶梯折扣/账期 | 企业/合同账户 | 净 GMV、客单价、转化 | 毛利率、价格一致性、转售/套利 |
| 商家工具/履约规则 | 商家 ID 或商家集群 | 按时履约率、商家留存 | 买家纠纷、净 GMV、履约成本 |
| 库存/供给分配 | 市场/geo 或 switchback | 可得率、满足率 | 价格离散、买卖双方公平性 |
| 销售激励/区域政策 | 销售代表/团队/区域 | 赢单率、激活率 | 跨区域污染、客户公平性 |

**指标默认**：30 天为主窗口；同时报 7/14/30 天累计；复购、留存、商家行为、衰减看 60/90 天或全量后 holdout。优先 Q2O、报价时延、报价接受率、净 GMV、买家留存、商家留存、按时履约、纠纷率、毛利率，少用点击类虚荣指标。

## 5. 最小输入

用户不必一次给全；先问这 6 项：

```text

想验证的假设：
实验对象 / 随机化单元：
主指标 + 护栏指标：
大致样本量或实验周期：
现在能看到的数据 / 表结构：
```

信息不足时，先给“最小可用 spec”，并明确哪些是假设、哪些需要补数据。

## 8. 停止条件

标准 A/B 不适用时，改用准实验、switchback 或书面判断：

- 没有稳定单元，或没有可测量的曝光。
- 人群太小，做不出可信 MDE，且没有敏感性杠杆。
- 干扰无法用 cluster/geo/时间切换控制。
- 干预不可逆、不合法、或伦理上不应随机。
- 指标在决策期内不可观测，且没有有效代理。
- 业务说不出“结果会改变哪个决策”。

## 9. 交付前自检

- [ ] 61 字段都有值，或 `N/A + 原因`。
- [ ] 主指标唯一，且与假设一致；护栏有 owner 和阈值。
- [ ] 单元、曝光、分析总体、估计量四者一致。
- [ ] 功效可复算；cluster DEFF、CUPED、流失都已说明。
- [ ] SRM、平衡性、曝光、污染、重复账户、血缘检查都在。
- [ ] 效应 = 绝对 + 相对 + CI + MDE + 业务价值。
- [ ] 多重比较、子群、长期窗口已预注册或标为探索性。
- [ ] 决策是全量/定向/迭代/停止/复测之一，并带灰度/holdout 计划。
- [ ] 文档、SQL、Dashboard、知识卡链接齐全。
